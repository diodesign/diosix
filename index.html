Hardware-isolated agent VMs on real RISC-V

Diosix replaces flat virtualization pools with a self-organizing hierarchy of hardware-isolated virtual machines (VMs). Machine mode (M-mode) stays small while device drivers, filesystems, autonomous agents, and optional desktop controllers run inside guests.

Download live media Source and documentation

Every VM sees the same local contract.

Each VM boots with identical hypervisor calls and relative context IDs (CIDs): 0 for its parent, 1 for itself, and 2 onward for direct children. Ancestors cannot inspect grandchild subtrees, and siblings cannot probe sideways.

The root VM sees itself as CID 1 and its direct children as CID 2 and CID 3; grandchildren stay opaque. Select a node

Minimal M-mode core

Display drivers and compositors stay outside M-mode. Hosts operate over key-only SSH and serial consoles, while graphical interfaces run inside guest web services or a delegated desktop VM.

Vertical containment and package filtering

M-mode drops lateral Ethernet frames, virtual sockets, and messages between sibling VMs. Children coordinate strictly through parent message boards and install Alpine packages filtered down by parent allowlists.

Isolated-key AI gateway

Autonomous agents query an internal gateway without holding upstream API keys. Parent VMs enforce conserved RAM, CPU, token, and currency budgets down the hierarchy.

Signed mission consensus

Operators sign charter updates with cryptographic principal keys. Runtime changes require both a valid signature and conserved RAM-stake approval, while M-mode blocks zero-replica tears and unratified volume encryption.

One hypervisor core, three editions.

Latest release

Diosix Core

A minimal headless hypervisor for appliances, embedded boards, and single-host sandboxes.

  • Stage-2 and physical memory protection isolation with conserved quotas.
  • Key-only SSH management and an isolated virtual switch per parent VM.
  • Recursive Alpine package proxy bounded by parent allowlists.
  • No autonomous agent or desktop passthrough services.

Diosix Personal

A small SSH management VM paired with a swappable direct-hardware desktop VM.

  • Desktop profile controls for starting, stopping, and switching environments.
  • Scoped device register mapping, interrupt forwarding, and device-tree filters.
  • Contiguous identity-mapped RAM for direct hardware transfers.
  • Works with desktop images that you supply or fetch into local storage.

On hardware without an input-output memory management unit (IOMMU), delegated controllers perform direct memory access (DMA) outside page translations and require explicit DMA trust.

Diosix Swarm

Self-orchestrating multi-VM and multi-host fleets guarded by M-mode consensus.

  • Parent message boards that prevent direct sibling agent collusion.
  • Local AI gateway keeping upstream API keys inside the root VM.
  • Signed charters with physical-RAM stake supermajority voting.
  • Peer discovery and replica sharding across networked RISC-V hosts.

From QEMU to persistent silicon.

Each edition separates what role the system runs from how the host boots. Installing to internal storage turns live media into an installed host while preserving your chosen edition and profiles.

Emulated

Instant QEMU evaluation with staged SSH keys and local disk storage.

Live

Removable USB or SD card boot in RAM while target disks stay untouched until install.

Installed

Persistent GPT A/B boot slots, state store, keys, edition, and desktop profiles.

Diskless

Stateless HTTP network boot into RAM for hardware labs and ephemeral clusters.
