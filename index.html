Bare-metal type-1 hypervisor · Zig · RV64

Hardware-isolated VM trees for bare-metal RISC-V.

Diosix organizes machines into recursive, symmetric virtual machine trees rather than flat hypervisor pools. The machine-mode core stays tiny while drivers, filesystems, autonomous agents, and optional desktop controllers live strictly inside isolated guests.

01 · Symmetric tree

Every VM sees the same local contract.

Every node in Diosix boots from the same minimal hypercall ABI and relative Context IDs: 0 for parent, 1 for self, and 2..N for direct children. Ancestors cannot peer into grandchild subtrees; siblings cannot probe sideways.

Root VM sees self (CID 1) and direct children Steward (CID 2) & Desktop (CID 3). Select any node above to shift perspective
i · Headless M-mode core

Drivers and UIs stay unprivileged

Paravirtual framebuffers and desktop compositors are absent from mainline M-mode. Hosts run headless over key-only SSH and serial, while user interfaces run inside isolated guest web services or delegated Personal hardware.

ii · Vertical containment

Anti-collusion boards & package attenuation

M-mode drops lateral sibling Ethernet frames, vsock connections, and whispers. Child VMs coordinate strictly upward via moderated parent boards and install Alpine packages filtered down by parent allowlists.

iii · Conserved budgets

Isolated-key thinking gateway

Autonomous agents request reasoning over an internal gateway without ever seeing upstream provider API keys. Parents slice RAM, CPU, token, and micro-USD budgets monotonically down the tree.

iv · Signed consensus

Stake voting & ransomware vetoes

Principals sign mission updates with Ed25519 keys. Runtime changes require conserved physical-RAM stake supermajority approval while M-mode blocks zero-replica tears and unratified volume encryption.

-Dedition=personal

Diosix Personal

A tiny SSH management domain paired with a swappable, direct hardware-passthrough desktop VM.

  • Core runtime + dsx personal profile manager
  • Scoped MMIO bars, PLIC IRQ forwarding & FDT filters
  • Contiguous identity-mapped RAM for device DMA
  • Bring-your-own or fetched desktop guest image

On processors without a hardware IOMMU, passed-through devices can DMA outside Stage-2 translations; require explicit DMA trust.

03 · Boot modes

From first QEMU test to persistent silicon.

Every edition separates what roles it runs from how the host boots. Installing onto storage transitions a Live session into an Installed system while preserving your edition and profiles.

01 · diosix.mode=dev

Emulated

Instant QEMU run with developer SSH keys and host storage.

02 · diosix.mode=live

Live

Removable USB/SD boot in RAM; disks stay untouched until install.

03 · diosix.mode=persistent

Installed

GPT A/B boot slots, state store, keys, edition, and profiles.

04 · diosix.mode=diskless

Diskless

Stateless HTTP netboot into tmpfs for hardware labs and clusters.
