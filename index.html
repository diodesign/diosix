Hardware-isolated VM trees for bare-metal RISC-V.

Diosix replaces flat VM pools with a self-organizing hierarchy of hardware-isolated virtual machines. Machine mode stays minimal while drivers, filesystems, autonomous agents, and optional desktop controllers run strictly inside guests.

Download live media Source & docs

Every VM sees the same local contract.

Every node boots with identical hypercall interfaces and relative Context IDs: 0 for parent, 1 for self, and 2..N for direct children. Grandchildren stay opaque to ancestors; siblings cannot probe sideways.

root → self CID 1 · children CID 2, CID 3 · grandchildren opaque Click any node

SSH-first M-mode core

Paravirtual framebuffers and desktop compositors stay out of machine mode. Hosts operate over key-only SSH and serial while user interfaces run inside guest web services or delegated Personal hardware.

Anti-collusion & attenuation

M-mode drops lateral sibling Ethernet frames, vsock links, and whispers. Children coordinate vertically through parent message boards and install Alpine packages filtered down by allowlists.

Isolated-key AI gateway

Autonomous nodes query an internal gateway without ever holding provider API keys. Parents enforce conserved RAM, CPU, token, and micro-USD budgets down the hierarchy.

Ed25519 mission consensus

Principals sign mission updates cleanly. Runtime changes require conserved physical-RAM stake supermajority approval while M-mode blocks zero-replica tears and unratified volume encryption.

Diosix Core

Minimal headless hypervisor for appliances, embedded targets, and single-host sandboxes.

  • M-mode isolation & recursive quotas
  • Key-only SSH & internal diosix0 switch
  • dsx pkg package attenuation server
  • Zero autonomous agent or display daemons

Diosix Personal

A small SSH management VM paired with a swappable, direct hardware-passthrough desktop guest.

  • Core runtime + dsx personal profile manager
  • Scoped MMIO bars, PLIC IRQ forwarding & FDT filters
  • Contiguous identity-mapped RAM for device DMA
  • Bring-your-own or fetched desktop image

Without an IOMMU, passed-through devices can DMA outside Stage-2 translations; requires explicit DMA trust.

Diosix Swarm

Autonomous, self-orchestrating multi-VM and multi-host fleet coordination with M-mode governance.

  • Core runtime + parent boards (dsx board)
  • Isolated thinking gateway (dsx agent proxy)
  • Ed25519 charters & conserved RAM-stake voting
  • Multi-host discovery & sharding (dsx swarm)

From QEMU to persistent silicon.

Every edition separates what roles it runs from how it boots. Installing onto storage transitions Live media into an Installed host while preserving your edition and profiles.

Emulated

Instant QEMU boot with developer SSH keys and host storage.

Live

Removable USB/SD boot in RAM; disks stay untouched until install.

Installed

GPT A/B boot slots, state volume, keys, edition, and profiles.

Diskless

Stateless HTTP netboot into tmpfs for hardware labs and clusters.
